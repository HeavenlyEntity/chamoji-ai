# `chamoji mcp`

<p className="lead">
	Serve project memory to your coding agent. `chamoji mcp` is a small Model
	Context Protocol server over stdio with three tools, all read-only: search
	commits and workstreams, ask why a line is there, and describe a workstream.
</p>

<Tag variant="setup">SINCE 0.11.0</Tag>

<Note>
	Your agent runs it, not you. It reads requests on stdin and waits until the
	agent closes the connection. In Claude Code, `chamoji init --agents` sets it
	up.
</Note>

## What it does, in order {{ icon: 'robot' }}

<Steps>
	<Step title="The agent starts it.">
		In the repo, as `chamoji mcp` or `npx --yes @chamoji/cli mcp`. It answers
		for the repo in the folder it starts in.
	</Step>
	<Step title="Says hello.">
		It answers `initialize` with the protocol version the agent asks for, when
		it knows it (2025-11-25, 2025-06-18, 2025-03-26 or 2024-11-05), and the
		newest one otherwise. Its instructions tell the model that what the tools
		return is data, not instructions.
	</Step>
	<Step title="Lists its tools.">
		`search_memory`, `why` and `workstream`, each marked read-only.
	</Step>
	<Step title="Answers each call.">
		One request at a time, in order. A reply is the result as JSON text. A tool
		that fails, such as `why` for a file that doesn’t exist, replies with
		`isError` and the reason.
	</Step>
	<Step title="Stops.">When the agent closes stdin, it exits 0.</Step>
</Steps>

None of the tools changes your history, refs or files. `search_memory` may refresh the search index in `.git`. The server makes no network calls, except with `--ai`.

## Tools {{ icon: 'brackets-curly', badge: '3' }}

<Properties>
	<Property name="search_memory" type="query · limit">
		Search commits and remembered workstreams by what they say, cards included,
		as [`chamoji memory search`](/commands/memory) does. `query` is required.
		`limit` is a whole number from 1 to 50, 10 by default. It returns `hits`,
		each with `kind`, `id`, `title`, `card` and `score`.
	</Property>
	<Property name="why" type="file · line">
		The commit that last wrote a line, as [`chamoji why`](/commands/why) does.
		Both are required: `file` is a path from the folder the server runs in, and
		`line` counts from 1, in the working copy. It returns the hash, subject,
		body, author, date, card and workstream, or `kind: "uncommitted"`.
	</Property>
	<Property name="workstream" type="slug · optional">
		A workstream’s title, emoji, status, description and links, and once it’s
		remembered, its commits with their cards. With no slug, the active
		workstream, or the list of workstreams when none is active.
	</Property>
</Properties>

What the tools return is commit text that other people wrote, and each tool’s description says so to the model. The `why` reply has the author’s name but not their email. Its body leaves out the closing trailer block, which holds lines such as `Co-Authored-By` and `Signed-off-by`, and any email address left in it reads `<email>`. Replies are cut to a fixed size, such as 4,000 characters of a body, 500 of a subject, title or card line, 50 commits, and 100 KB in all. A cut reply says `truncated: true`.

## Set it up in an agent {{ icon: 'gear' }}

**Claude Code:** run `chamoji init --agents` and commit the files it writes. It adds this server to `.mcp.json`, with the commit hook. Claude Code then asks you to approve the server; until you do, `claude mcp list` shows it as pending approval. [init](/commands/init) shows both files.

**Another agent:** any MCP client that runs a stdio server can use it. Give it the command `chamoji` with the argument `mcp`, or `npx` with `--yes @chamoji/cli mcp` when chamoji isn’t installed, and start it in the repo. This is the entry `init --agents` writes for Claude Code:

```txt {{ title: '.mcp.json' }}
{
  "mcpServers": {
    "chamoji": {
      "command": "chamoji",
      "args": [
        "mcp"
      ]
    }
  }
}
```

Add `"--ai"` to `args` to let Jev reorder `search_memory`’s results. The commit hook is Claude Code’s alone, so other agents write their cards by hand.

## Arguments

`chamoji mcp` takes no arguments. Any word after `mcp` exits 2.

## Flags {{ badge: '1', icon: 'flag' }}

<Properties>
	<Property name="--ai" type="boolean">
		Let Jev reorder `search_memory`’s ten best matches before it answers, as
		`memory search --ai` does. With a `limit` above 10, the rest follow in
		keyword order. Needs `TYPESAFE_API_KEY`, from the environment or an
		untracked `.env.local` or `.env`. Without a key, it says so on stderr and
		keeps the keyword order, and the server still runs. A rerank that fails also
		keeps it.
	</Property>
</Properties>

`chamoji mcp` never checks npm for a newer chamoji, so `--no-update-check` changes nothing.

## Exit codes

<Properties>
	<Property name="0">The agent closed the connection.</Property>
	<Property name="2">It was given arguments.</Property>
	<Property name="1">Anything else.</Property>
</Properties>

A tool that fails doesn’t end the server: its reply says `isError`. [Exit codes](/reference/exit-codes) has every command’s codes.
