# `chamoji why`

<p className="lead">
	Ask why a line of code is there. chamoji blames the line in your working copy
	and prints the commit that wrote it, with its author, date and intent card. It
	only reads git: nothing is changed or sent anywhere.
</p>

<Tag variant="setup">SINCE 0.11.0</Tag>
<Tag variant="ci">--json FOR CI AND AGENTS</Tag>

<Note>
	The file is relative to the folder you run chamoji in, as with `git blame`. In
	`src/`, ask for `picker.js:2`, not `src/picker.js:2`.
</Note>

## What it does, in order {{ icon: 'magnifying-glass' }}

<Steps>
	<Step title="Blames the line.">
		In your working copy, so the line numbers are the ones your editor shows. It
		follows moved lines and renames, and skips changes that only touched
		whitespace.
	</Step>
	<Step title="Reads the commit.">
		Its short hash, subject, author and date, and its intent card: the `Why:`,
		`Constraint:`, `Gotcha:` and `Follow-up:` lines in its message.
	</Step>
	<Step title="Judges the reason.">
		It checks whether the `Why:` line says why, with a local check that sends
		nothing anywhere. A thin Why, such as “fix bug”, gets a notice. A thin or
		missing one also gets clues: the PR number from the subject, and up to three
		commits to the same file in the 14 days before it whose cards do say why. It
		only reads git.
	</Step>
	<Step title="Puts added reasons first.">
		If someone ran `chamoji why --amend` on the commit, the reason they added
		comes first, ending in `(added later)`, ahead of the commit’s own lines. The
		Why is judged with the added reason included.
	</Step>
	<Step title="Adds the workstream.">
		When the commit has no card, or a thin one, and names a workstream, it shows
		that workstream’s title and status, from project memory or, failing that,
		`.chamoji/workstreams.yml`.
	</Step>
	<Step title="Prints it.">
		A commit without a card says “This commit records no intent.” A thin Why
		prints “This reason is thin. Look at the PR, issue and nearby commits too.”
		A line you haven’t committed yet says so and exits 0.
	</Step>
</Steps>

[Project memory](/guides/project-memory) explains intent cards, and how to write them.

## Arguments

<Properties>
	<Property name="file:line" type="string · required">
		The file and the line number, from 1, such as `src/auth.ts:42`. It splits at
		the last colon, so a file name may hold colons. Give exactly one: none, or
		more than one, exits 2. Anything that isn’t `file:line`, such as a missing
		line number or line 0, exits 1.
	</Property>
</Properties>

## Flags {{ badge: '2', icon: 'flag' }}

<Properties>
	<Property name="--json" type="boolean">
		Print the blame result as JSON on stdout. It’s `{"kind": "uncommitted"}` for
		a line you haven’t committed, or `kind: "commit"` with the whole commit as
		chamoji reads it: hash, author name and email, date, subject, body, gitmoji,
		trailers, `card` when there is one, and `workstream` as a slug. It doesn’t
		look up the workstream’s title. A commit result also has `whyQuality`
		(`ok`, `thin` or `none` when there is no card), `whyReasons` (why a Why was
		judged thin) and `clues` (`pr`, when the subject names one, and `nearby`)
		when the reason is thin or missing. The exit codes stay the same.
	</Property>
	<Property name="--amend" type="string">
		Add a better reason to an old commit. The target is a commit hash, or a
		`file:line` whose commit is blamed, and everything after it is the reason:
		`--amend <target> <reason>`. It goes in a git note in
		`refs/notes/chamoji`, so the commit and its hash stay as they are. A reason
		with no `Why:` line is kept as `Why: <reason>`. A reason that is thin too is
		refused and nothing is written. Adding another replaces the first. Every
		reader, including `chamoji why`, the MCP `why` tool and memory search, shows
		the added reason first.
	</Property>
	<Property name="--no-update-check" type="boolean">
		Don’t check npm for a newer chamoji. See [the update
		notice](/install#the-update-notice).
	</Property>
</Properties>

```txt {{ title: 'chamoji why src/picker.js:2' }}

Sam Rivera, 2026-11-05

Why: the form crashed when the field was cleared
Gotcha: callers still compare with undefined in two places
```

A commit with no card, made while a workstream was active:


```txt {{ title: 'chamoji why src/picker.js:5' }}
c41d9e2 🐛 Fix the picker (#31)

Why: fix bug
This reason is thin. Look at the PR, issue and nearby commits too.
PR: #31
Nearby: 39a81ce 🐛 Return null for an empty date
```

## Share added reasons {{ icon: 'terminal' }}

Added reasons live in a git note, and git doesn’t push notes unless you ask.
Send yours, and fetch a teammate’s:

```sh
git push origin refs/notes/chamoji
git fetch origin refs/notes/chamoji:refs/notes/chamoji
```

Until you fetch, your copy only has the reasons added in it. Nothing is lost:
the commit’s own lines still show.

## Exit codes

<Properties>
	<Property name="0">
		It found the commit, or the line isn’t committed yet.
	</Property>
	<Property name="2">
		No location, or more than one. With `--amend`, no target or no reason.
	</Property>
	<Property name="1">
		Anything else, such as a location that isn’t `file:line`, a file or line
		that doesn’t exist, a repo with no commits yet, or outside a git repo. With
		`--amend`: a line that isn’t committed yet, a target that isn’t a commit, or
		a reason that is thin too.
	</Property>
</Properties>
