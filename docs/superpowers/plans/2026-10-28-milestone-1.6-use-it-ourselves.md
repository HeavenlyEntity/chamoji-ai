# Milestone 1.6: Use It Ourselves Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** chamoji-ai, the product repo, cuts its releases with chamoji, with no manual changelog or version edits, and the friction we found is fixed.

**Architecture:**

- `pnpm release` is a Node script that drives the built CLI: `next-version` → bump both packages → `changelog --release` → commit → tag.
- Publishing stays manual (`pnpm publish -r`) until milestone 2's release workflow.
- The CLI reads `TYPESAFE_API_KEY` from `.env.local` or `.env` in the working directory when the environment doesn't set it.

**Tech stack:** as milestone 1. `node:util` `parseEnv` (Node ≥ 22).

**Spec:** `docs/ROADMAP.md`, milestone 1.6.

## Global constraints

- **Only `TYPESAFE_API_KEY` is read from env files.** No other variables are loaded into the process, and the key is never printed.
- **An environment variable always wins over a file.** `.env.local` wins over `.env`.
- **`pnpm release` refuses to run** on a dirty working tree, or on a branch other than `main`.
- **`pnpm release` stops with exit 3** when `next-version` says no release is needed. It never pushes or publishes.
- Commits use gitmoji messages and end with the `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` line.

## Review focus

1. **A `.env.local` with other secrets,** such as `GITHUB_TOKEN`. They must not reach `process.env` or any request. Covered in Task 1.
2. **Quoted values and Windows line endings** in `.env` files. Covered in Task 1 (`parseEnv` handles both; tested).
3. **A release run interrupted halfway.** It must leave nothing half-written. The script checks everything first and commits last. Covered by Task 2's ordering.

### Task 2: `pnpm release`

**Files:**

- Create: `scripts/release.mjs`
- Modify: root `package.json` (a `release` script)

**Behaviour:**

1. Check that the working tree is clean and the branch is `main`, or stop with exit 1.
2. Run `pnpm build`.
3. Run `node packages/cli/dist/cli.js next-version`. On exit 3, print "nothing to release" and exit 3.
4. Set `version` in `packages/core/package.json` and `packages/cli/package.json`.
5. Run `chamoji changelog --release v<version> --output CHANGELOG.md`, then Prettier on it.
6. `git commit -am "🔖 Release v<version>"`, then `git tag v<version>`.
7. Print the next steps: `git push --follow-tags` and `pnpm publish -r`.

`--dry-run` prints the version and the changelog section, and changes nothing.

**Steps:**

- [ ] Implement the script.
- [ ] Run `pnpm release --dry-run` and confirm the output.
- [ ] Commit `🔨 Add pnpm release script`.
